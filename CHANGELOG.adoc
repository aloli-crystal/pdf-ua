== v0.1.1 — 2026-06-02 — veraPDF-certified PDF/UA-1 output

=== Verified

* A document built with `PDF::UA::Document` (title + language +
  tagged structure with marked content via `page.tag`, embedded
  TrueType font) is reported **`isCompliant="true"`** by **veraPDF
  1.30.1** on the PDF/UA-1 profile : 106 rules passed, 0 failed.
+
CAVEAT : veraPDF validates the *machine-checkable* subset of PDF/UA-1
  (the automatable Matterhorn Protocol checkpoints). A clean veraPDF
  pass means no automated failure ; full PDF/UA conformance still
  requires human review of the non-automatable checkpoints
  (meaningful alt text, logical reading order, etc.). This is a
  strong result, not a complete certification.

=== Changed

* Dependency bumped to `pdf ~> 0.7.6`.

== v0.1.0 — 2026-06-02 — Bootstrap (J4, palier 1)

=== Added

* Initial PDF/UA accessibility-profile layer over `aloli-crystal/pdf`
  (requires pdf ~> 0.7.5).
* `PDF::UA.configure(doc)` — declares the pdfuaid identification
  (`pdfua_part = 1`) and turns on `display_doc_title`.
* `PDF::UA.violations(doc)` — document-level checks : not tagged,
  missing language, missing title, DisplayDocTitle off, missing
  pdfuaid — each traced to its ISO 14289-1 clause.
* `PDF::UA.conformant?(doc)`.
* `PDF::UA::Document` — auto-configures on construction and, in the
  default strict mode, raises `PDF::UA::ConformanceError` on
  `write`/`save` if a precondition is unmet.
* Composes with `pdf-a` : a document may be configured for both
  PDF/A and PDF/UA.
